## Sugerencias (no bloquean)
1. GitHub desactiva los workflows programados de un repo público tras 60 días sin actividad en el repo. Si después de la entrega no hay commits, el keep-alive se apagará solo (GitHub avisa por email). Conviene anotarlo en el README (T15) o reactivarlo a mano cuando llegue el aviso.
2. Si el login devuelve 200 con un cuerpo que no es JSON, el job falla bien pero con el mensaje de `jq` en vez de un `::error::` propio. Con `token="$(jq ... "$body")" || fail "Login: la respuesta no es JSON"` quedaría más claro. jq no vuelca el contenido en sus errores, así que no filtra nada.
3. Con el servidor caído, `curl -sS` imprime el host (`Could not resolve host: <ref>.supabase.co`). GitHub enmascara el secret `SUPABASE_URL` entero, pero no el host suelto. No es un secreto de verdad (la URL de Supabase ya es pública en el bundle como `NEXT_PUBLIC_SUPABASE_URL`), así que no bloquea.
4. El token va en los argumentos de curl (`-H "Authorization: Bearer $token"`), visible en la lista de procesos del runner. El runner es efímero y de un solo job, así que no hay riesgo práctico. Si se quiere evitar, se puede pasar con `-H @archivo`.
