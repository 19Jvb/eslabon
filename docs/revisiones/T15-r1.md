## Fallos (bloquean)
- F-1 [D-02] `README.md:77-93`, «Ejecutarlo en local». Los pasos no bastan para que funcione lo que promete la tabla de la l. 92 («`npm run e2e` | E2E en local») ni el botón demo en local. Faltan dos pasos manuales:
  - (a) **crear el usuario demo y marcarlo como demo, y crear el usuario de E2E** en el proyecto de Supabase. La migración no lo hace: `supabase/migrations/20261126172934_init.sql:80` lo deja para el SQL Editor (`update auth.users set raw_app_meta_data = raw_app_meta_data || '{"demo": true}' where id = '<demo user id>'`).
  - (b) **`npx playwright install chromium`**: `npm ci` no descarga los navegadores de Playwright.
  - Reproducir: en un proyecto de Supabase nuevo, seguir solo las l. 80-85 y ejecutar `npm run e2e`. Sin (b), Playwright aborta porque no encuentra el ejecutable de Chromium. Con (b) pero sin (a), `e2e/rls.spec.ts:20` lanza «No se pudo iniciar sesión como DEMO» y «Probar con la cuenta demo» no entra en `/app`. Con la demo creada pero sin la marca, `e2e/rls.spec.ts:90` (la demo no puede cambiar su contraseña) falla.
  - Esperado: el README menciona estos dos pasos (basta con una línea cada uno).
- F-2 [D-02] `README.md:83`: el comentario de `db push` dice «migraciones: esquema, RLS, trigger de la demo **y datos de ejemplo**». No es cierto: las migraciones no insertan datos. `supabase/migrations/20261126231955_sample_data.sql` solo crea la función `public.load_sample_data(p_today)`, y los datos se crean cuando un usuario con sesión pulsa «Cargar datos de ejemplo» (README:23). Reproducir: tras `db push` en un proyecto vacío, `select count(*) from public.habits` → 0. Esperado: algo como «… trigger de la demo y la función de datos de ejemplo».
